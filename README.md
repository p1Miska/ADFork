# AdGif — троллинг-мод для Fabric 1.21.11

Показывает случайную gif-«рекламу» посередине экрана на 7 секунд, во время
которой персонаж не может двигаться и ничего делать, но мир продолжает жить
(мобы, время суток и т.д. не останавливаются).

## Куда положить гифку

Положи файл гифки сюда (создай папки, если их нет):

```
src/main/resources/assets/adgif/textures/gui/ad.gif
```

Если хочешь другое имя/путь — поменяй `gifPath` в конфиге (см. ниже),
формат: `"адгиф:путь/от/assets/adgif/"`, например
`"adgif:textures/gui/my_ad.gif"`.

Гифка должна иметь **прозрачный фон** (альфа-канал/прозрачный цвет в самом
gif) — мод не рисует никакой подложки, только пиксели гифки поверх игры.

## Звук

GIF не умеет хранить звук вообще — это ограничение формата, а не мода.
Поэтому звук проигрывается отдельным файлом синхронно с началом показа гифки:

```
src/main/resources/assets/adgif/sounds/ad.ogg
```

Файл обязательно должен быть в формате **OGG Vorbis** (единственный формат,
который понимает звуковой движок Minecraft) — mp3/wav не сработают, их нужно
предварительно сконвертировать (например, через online-audio-converter.com
или convertio.co).

Как получить прозрачную гифку из видео с зелёным фоном + звук в ogg — см.
инструкцию, которую прислал автор мода в чате (ezgif.com для видео,
online-audio-converter.com/convertio.co для звука).

Звук можно отключить или сделать тише через `playSound` / `soundVolume` в
конфиге.

## Сборка

Просто запушь репозиторий на GitHub — Actions (`.github/workflows/build.yml`)
соберёт мод автоматически и положит `.jar` в Artifacts вкладки Actions.

Локально (если есть Java 21 и Gradle 8.14+):

```
gradle build
```

Готовый мод будет в `build/libs/adgif-1.0.0.jar`.

## Настройка (config/adgif.json)

Файл создаётся автоматически при первом запуске мода, в папке `config`
вашего инстанса Minecraft. Поля:

| Поле | Что делает |
|---|---|
| `gifPath` | путь к гифке (см. выше) |
| `scale` | множитель размера гифки. `1.0` — оригинальный размер, `2.0` — вдвое больше, `0.5` — вдвое меньше |
| `durationSeconds` | сколько секунд держится реклама (по ТЗ — 7) |
| `chanceRandom` | шанс (0–1) случайного срабатывания |
| `randomCheckIntervalSeconds` | как часто (в секундах) проверяется случайный шанс |
| `chanceOnDamage` | шанс при получении урона |
| `chanceOnAttack` | шанс при ударе (по мобу/игроку) |
| `chanceOnAction` | шанс на любое другое действие: сломать блок, открыть верстак/сундук/печку, использовать предмет |

Значения по умолчанию соответствуют ТЗ: 40% / 60% / 50% / 15%, 7 секунд.

Пока реклама активна — новые срабатывания любых триггеров просто
игнорируются (не встают в очередь, не продлевают показ).

## Как это устроено (коротко)

- Мод полностью клиентский (`"environment": "client"` в `fabric.mod.json`) —
  не требует установки на сервер, работает и в одиночной игре, и на
  ванильных серверах.
- Обнаружение урона — сравнение здоровья игрока между тиками (без миксинов).
- «Удар» и «действия» — стандартные события Fabric API
  (`AttackEntityCallback`, `AttackBlockCallback`, `UseBlockCallback`,
  `UseItemCallback`, `PlayerBlockBreakEvents`), которые также **отменяются**,
  пока реклама на экране — это и даёт эффект «нельзя ничего делать».
- Заморозка передвижения — каждый тик обнуляются нажатия клавиш движения,
  прыжка, инвентаря и т.д. Мир при этом продолжает тикать как обычно —
  мод нигде не ставит игру на паузу.
- Гифка декодируется через стандартный `javax.imageio` (учитывает
  прозрачность, позиционирование кадров и disposal-методы), каждый кадр
  заливается в текстуру и рисуется поверх HUD.

## ⚠️ Важное предупреждение про версию 1.21.11

Изначально я собрал проект на официальных мэппингах Mojang, но выяснилось,
что текущий Loom (1.14.x) падает на них для 1.21.11 с известным багом
("Cannot remap modifiers") — из-за него вообще ни один класс Minecraft не
резолвится. Официальные мэппинги без Yarn станут нормой только с версии
Minecraft 26.1. Поэтому проект переведён на **Yarn** (`1.21.11+build.4`) —
это проверенный, стабильный набор мэппингов именно для 1.21.11, и весь код
переписан под его именование классов (`Identifier`, `MinecraftClient`,
`PlayerEntity`, `DrawContext` и т.д.).

Единственное место, где всё ещё может понадобиться правка — вызов
`drawContext.drawTexture(...)` в `AdGifClient.java`: Mojang в это время
переделывал рендер-пайплайн текстур, и точная сигнатура этого метода могла
чуть измениться. Если сборка упадёт именно на нём — пришли лог, поправлю
конкретный вызов под актуальную сигнатуру.

**Если сборка в Actions упадёт** — просто скопируй мне текст ошибки из лога
Actions, я поправлю конкретную строчку.
